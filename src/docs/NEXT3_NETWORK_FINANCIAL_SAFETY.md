# Next 3 — Network & Financial Request Safety

## 130 — Session Refresh Concurrency
Token refresh uses one shared Future so simultaneous safe requests wait for the same refresh operation instead of starting competing refreshes.

## 131 — Financial Mutation Replay Guard
Deposit/withdrawal/reward/other financial mutations must not be automatically replayed after a 401. The app must query the transaction status or rely on server reconciliation.

## 132 — Request ID + Idempotency Contract
Every API request gets an `X-Request-ID`. Financial mutations can attach a backend-enforced `Idempotency-Key` generated by the client. The backend remains authoritative and must persist uniqueness atomically.

Flutter/Dart build still requires the Flutter SDK; these changes were checked statically in the current source tree.
